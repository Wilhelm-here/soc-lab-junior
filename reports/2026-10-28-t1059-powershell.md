# INC-001 — Encoded PowerShell Execution (T1059.001)

**Дата:** 2026-10-28 | **Автор:** SOC Analyst | **Severity:** High | **Статус:** Closed

## Summary
На хосте ictim (10.10.10.20) зафиксирован запуск PowerShell с использованием кодированной команды (-EncodedCommand). Техника используется для обхода детектирования по сигнатурам командных строк.

## Environment
- **Хост:** victim (Windows 11, IP 10.10.10.20)
- **SIEM:** Wazuh 4.14.9 (10.10.10.10)
- **Источники логов:** Sysmon EventID 1, Security EventID 4688

## Detection
- **Поле:** win.eventdata.commandLine
- **Паттерн:** содержит -enc или -EncodedCommand
- **Сработавшее правило:** ule.id = ... (найди ID правила в JSON, которое выпало в логе).

## IOCs
- Командная строка: powershell.exe -EncodedCommand <base64>
- Хеш процесса: отсутствует (техника полностью локальная).

## MITRE ATT&CK
- **T1059.001**: Command and Scripting Interpreter: PowerShell

## False positives
Возможны при работе легитимных установщиков, использующих упакованные скрипты (например, Chocolatey, некоторые корпоративные софты). Отличать по родительскому процессу (parentImage) и подписи бинаря.

## Gaps
- Не хватает логирования Script Block (4104), если скрипт не запускает дочерний процесс. (Проверить, настроено ли ScriptBlockLogging).

## Recommendation
1. Включить детальный аудит PowerShell (Script Block Logging) для 4104.
2. Ограничить Execution Policy (AllSigned) для критичных узлов.
3. Добавить в правило исключение для известных легитимных установщиков.

## Lessons learned
Проверка -EncodedCommand показала, что Sysmon ловит это даже без 4104. Для полной картины нужен 4104.
